# Kongono Model Invocation Application

`kongono/model-invocation-application` is the optional Experimental Phase 14F
application boundary for one exact-current invocation profile. It validates one
explicit Phase 14C plan source and artifact, emits deterministic inert PHP
wiring, loads one explicit exact-current generated file, binds one directly
supplied application adapter, and delegates one terminal synchronous operation
to a fresh Phase 14D runtime.

Use it when an application already owns one typed invocation plan, its exact
artifact, an output directory, and the adapter instance whose identity the plan
declares. Do not use it to select a provider, discover an adapter or credential,
retry or fall back, retain a conversation, schedule work, or authorize an Agent
capability.

One application instance has finite `ready`, `active`, and `retired` states and
can run only once. The application returns the exact detached Phase 14D runtime
result. Phase 14D continues to own every opened adapter session and its close
attempt. Phase 14E remains a separate optional caller-controlled reduction from
an eligible result to inert Agent proposal evidence.

Phase 14G's optional
[`kongono/model-invocation-inspection`](../model-invocation-inspection/README.md)
may revalidate one explicit profile/wiring pair and summarize the completed
detached result. It never loads generated PHP, starts this application, invokes
the adapter, or replays the result.

Generated wiring is content-addressed derived evidence. Publication is
contained, atomic, initial-only, no-clobber, and idempotent for identical bytes;
loading requires one explicit path and does not scan. Trusted generated and
in-process PHP are not sandboxed.

The package contains no provider SDK or first-party adapter, credential lookup,
provider/profile registry or default, automatic retry/fallback, second profile,
CLI, retained session, background work, deployment behavior, Phase 13 port, or
Phase 14E dependency. Profiles, plans, results, receipts, costs, usage, hashes,
and wiring are evidence, never authentication, authority, grants, effects, or
proof of effect. Kongono remains usable without AI, a provider, credentials, an
account, or a network.
