# Kongono OpenAI Responses Inspection

`kongono/model-provider-openai-responses-inspection` is the optional
Experimental Phase 17G upper evidence leaf. It reconstructs one explicit
exact-current OpenAI Responses application profile and can relationship-check
one optional detached terminal model-invocation result.

## Use and output

Use it when an application or developer tool needs deterministic,
presentation-neutral evidence about accepted Phase 17 composition without
starting an application, invoking an adapter, loading generated PHP, reading a
body, or contacting a provider. The result uses canonical schema
`kongono.openai-responses-inspection` version 1 and contains only Protected
digests, closed tokens, booleans, and bounded Safe counts.

Do not use it to discover a provider, validate an account or entitlement,
authorize work, replay an operation, inspect model content, or prove live
compatibility. Currentness is relative only to the supplied accepted profile.

## Optional runtime evidence

The optional `InvocationRuntimeResult` must already be terminal, retired, and
cleanup-complete. Receipt, result, profile, request, event, usage, and cost
relationships are checked without reading text, structured values, action
arguments, response identifiers, foreign failures, request or response bodies,
headers, endpoints, credentials, or transport objects. Failed, cancelled, and
rejected outcomes remain honest evidence and are never converted to success.

## Projections and roles

Graph projection accepts only an explicit matching-role Safe aggregate view;
absence is explicit and the OpenAI-to-Graph relationship remains
not-established. Observation and Security Audit projectors construct values but
do not record or export them. Chie, Hantei, and Oshie tokens select explain,
verify, and teach evidence only. No role is executed. Independent verification
reconstructs the permitted evidence shape without calling the deriver, repairing
a candidate, or certifying itself.

## Side effects, lifecycle, and stability

The package is offline, read-only, stateless, and safe for repeated, nested, or
interleaved calls. It performs no filesystem, environment, time, randomness,
process, DNS, socket, TLS, HTTP, credential, provider, application, runtime,
recording, exporting, retry, replay, repair, or background effect. It has no
start/stop lifecycle and retains no input or output across calls.

Consumer-facing types are Experimental. Canonicalization and diagnostics are
Internal. The package provides no live-provider proof, provider certification,
compatibility guarantee, checkpoint, Stable claim, or production-readiness
claim.
