# Minimal Application Events Example

This copy-once project demonstrates explicit, synchronous application-owned events. It uses the separately optional Experimental `kongono/event-contract` and `kongono/event-runtime` packages. Its event, policy and effects are editable application code, not framework API.

In this Kongono checkout, the Composer path repository `../../packages/*` resolves the four local libraries. For manual local dependency setup, run `composer install --no-dev --no-interaction --no-scripts --no-plugins` from this directory with Composer network access disabled. The locked packages are local path copies; the example does not bundle Composer or PHPUnit. After setup, run `php bin/demo.php` or the application-owned `composer demo` script. The demo dispatches one validated `InvoicePaid` event to receipt then ledger handlers. Both effects and the policy are in memory. It sends no mail, writes no business file or database row, uses no provider or credential, and makes no network request. The fixed sample policy is not production authentication or authorization.

`EventComposition::create` explicitly loads the event class, then directly supplies two handlers and their ordered registration set to the dispatcher. A `::class` string alone does not load a class. Each handler accepts the native `ApplicationEvent` parameter, narrows to `InvoicePaid`, checks current application authorization immediately before its own effect, and invokes its supplied effect only on strict approval. Replace the sample authorizer and effects with reviewed application-owned collaborators. A successful dispatch grants no authorization, transaction, durability, delivery or exactly-once claim.

Keep payloads small and use immutable values. PHP `readonly` does not deeply freeze referenced objects; this example carries only a validated scalar identifier. Handlers and their resources remain caller-owned. The dispatcher retains the registration set and its handlers; supplied closures may retain their own captured data. Create fresh operation-specific composition if closures capture operation data. Reuse a dispatcher only with collaborators designed to keep operation data isolated. Handler failures escape as the original `Throwable`; earlier effects remain, later effects do not run, and no retry or rollback occurs. The outer demo prints only a fixed failure token, never native exception text, trace or payload.
