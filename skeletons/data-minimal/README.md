# Minimal Kongono data application

This copy-once skeleton demonstrates Kongono's Experimental generated data
application workflow. Install its locked dependencies, then run:

```text
composer app:build
composer app:check
```

Both commands report exact identities for the mapping artifact, generated data
access, Composition artifact, and generated wiring. Build publishes immutable
content-addressed files under `var/kongono/build/`; check writes nothing and
fails unless the exact current files already exist. No current/latest pointer,
newest-file selection, overwrite, or generated-file fallback exists.

The application contains one final readonly record, one generated four-operation
repository, and one typed operation root. The composition source selects the
existing PostgreSQL 17 compiler and accepts a `DatabaseConnector` as its sole
startup input. A host constructs the connector explicitly and passes it to
`Runtime::start()`; the skeleton never reads credentials from environment,
globals, files, or command-line arguments.

The copied application owns every non-generated byte. Kongono never silently
upgrades, merges, or overwrites a copied skeleton, and this template is not a
listener, deployment entrypoint, migration runner, ORM, or production-readiness
claim.
