# ADR 0074: Generated Assembly and Web Runtime Integration

- **Status:** Accepted
- **Date:** 2026-08-23
- **Decision scope:** Phase 5F generated-assembly loading and existing web lifecycle integration
- **Stability:** Experimental

## Context

Phase 5E can generate, validate, and optionally publish deterministic typed PHP
wiring, but intentionally supplied no production loading boundary. The existing
Web Application, Web Runtime, and PHP-CGI packages already own distinct Kernel
operation, delivery, and front-controller responsibilities. Phase 5F needs one
explicit bridge without moving those responsibilities or introducing runtime
service location.

## Decision

`GeneratedWiringLoader` receives an explicit resolved application root, exact
Composition artifact bytes, and one exact generated PHP file. It admits only an
ordinary exact-case contained file with the required content-addressed basename.
It performs structural and exact-current validation, checks for existing class
collisions, reverifies the stable file snapshot, and only then requires that one
file. It does not scan, select a latest artifact, rebuild, repair, download,
mutate autoloading, or fall back.

`LoadedGeneratedWiring` is a one-use startup boundary. After loading, bounded
reflection may inspect only the exact generated application and operation
classes and their startup/root methods. Ordered inputs must match the generated
`start()` parameter count and native object types before invocation. Application
construction failures and generated cleanup retain their existing exact
Throwable behavior.

## Supported web profile

The Phase 5F web profile has exactly one application root with native return
type `Kongono\Web\Runtime\GeneratedWebRuntimeRoot` and no operation roots.
`GeneratedWebRuntimeBootstrap` carries exactly one existing
`TrustedDeveloperBootstrapPermission`. `GeneratedWebRuntimeRoot` constructs the
existing `WebRuntimeAdapter` from one `WebApplication` and that permission.
`GeneratedWebRuntimeApplication` owns the generated application boundary and
the typed root; it exposes only the typed runtime, explicit shutdown, and
retirement observation.

`WebApplication` is directly constructible from `KernelInterface` and an
explicit `RequestHandlerInterface`. Construction boots the Kernel once. The
existing `boot()` factory still constructs the real routing and middleware
pipeline, then delegates to the constructor without a second boot.

## Lifecycle ownership

The generated application assembly owns construction and final reverse cleanup.
Its declared Web Application cleanup is `shutdown`; Kernel is not also declared
as generated cleanup. Web Application continues to own exactly one Kernel
operation per handled request. The generated web path never calls the generated
`beginOperation()`. Web Runtime continues to own one send and one delivery close.
PHP-CGI continues to own capture, conversion, emission, close, and front-
controller shutdown. `CgiGeneratedFrontController` only supplies the generated
application's runtime and shutdown closure to the existing
`CgiFrontController::run()`.

## Failure and security contract

`KGN-COMPOSITION-1017` reports generated-wiring load failure and
`KGN-WEB-RUNTIME-1003` reports an invalid generated web profile. Their Safe
context contains only fixed bounded violation tokens. Package-owned exception
stringification does not disclose paths, bytes, runtime inputs, object data,
environment data, secrets, or native messages.

Generated bytes are inert until exact current validation succeeds. Reflection
is startup-only; request handling performs no reflection, discovery, constructor
inference, attribute scan, autowiring, service lookup, or generated operation
creation. The loader and runtime bridge are never application-service
dependencies.

## Dependency and exclusions

Web Runtime adds the sole new edge to Composition. PHP-CGI already depends on
Web Runtime. Kernel, Routing, HTTP Server, Web Application, and PHP-CGI gain no
Composition dependency.

This decision adds no container, resolver, service locator, route schema,
transport, CLI, application skeleton, deployment automation, checked-in
generated artifact, OPcache/preload policy, Graph/DI integration, or Phase 5G
behavior.
