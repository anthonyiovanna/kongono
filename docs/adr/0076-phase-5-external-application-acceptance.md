# ADR 0076: Phase 5 External Application Acceptance

- Status: Accepted
- Date: 2026-08-23
- Phase: 5H

## Context

Phase 5A through 5G establish the application Composition contract, deterministic artifacts, generated typed wiring, fail-closed loading, existing web-lifecycle integration, and one copy-once minimal skeleton. Closing the milestone requires evidence across the real installed application boundary rather than inference from package tests or successful exit codes alone.

## Decision

Phase 5 external acceptance is root-owned test tooling. It is not a framework runtime API, package, application dependency, installer, listener, deployment mechanism, or production feature.

The harness copies exactly the 15 skeleton-owned files into a fresh GUID-named system-temporary workspace. It mirrors the lock-required local package roots as ordinary byte-preserving files, rewrites only the copied application's path-repository location, disables Composer plugins, and invokes real local non-interactive Composer, PHP, and PHP-CGI processes. The accepted locked dependency set runs with network access disabled.

Acceptance validates exact artifacts, identities, response bytes, bounded failures, mutation sets, lifecycle state, and cleanup. It does not infer success from an exit code alone. Its public result is compact canonical JSON with a fixed schema/version, the 28 ordered scenario records, aggregate counts, and deterministic content identities.

Copied source is application-owned. Derived output is content-addressed and selected only by exact current derivation. There is no directory scan, latest/current pointer, fallback, or request-time build. Build may expose only a complete valid pair; check and run are write-free. Missing, stale, invalid, partial, tampered, crossed, renamed, linked, outside-root, or changing state fails closed.

Kernel retains operation ownership. Web Application retains application lifecycle and one operation per request. Web Runtime retains delivery ownership. Generated boundaries retain generated cleanup. PHP-CGI retains one-request conversion, emission, and front-controller failure composition.

## Security and failure behavior

The harness inspects raw stdout and stderr. Network-denied execution and unrelated secret variables cannot change supported results. Rejected path-like, source-like, native-error-like, and secret markers cannot cross the command boundary. Failures expose fixed bounded text, not paths, source/generated bytes, native messages, stack traces, environment values, credentials, or secrets.

Every external root is resolved before use, excluded from repository/home/broad-path deletion, removed in `finally`, and proved absent. Cleanup failure fails acceptance.

## Consequences

`composer acceptance:phase5` supplies reproducible evidence for the supported pre-1.0 application-composition slice. It remains separate from `composer quality` and does not enlarge production authority.

Phase 5 closure does not assert Stable API, 1.0, full-framework status, production readiness, deployment certification, automatic skeleton upgrade, or any Phase 6 capability.

## Rejected alternatives

- Treating package tests or exit codes alone as external acceptance.
- Installing through symlinked local packages or enabled Composer plugins.
- Scanning output or selecting a mutable latest/current pointer.
- Repairing, rebuilding, or falling back during check or request handling.
- Exposing temporary paths, native failures, environment data, or adversarial markers.
- Retaining temporary workspaces after success or failure.
