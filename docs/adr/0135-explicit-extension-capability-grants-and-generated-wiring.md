# ADR 0135: Explicit Extension Capability Grants and Generated Wiring

- Status: Accepted
- Date: 2026-08-30
- Phase: 12E

## Context

Phase 12D produces deterministic admission and attributable Graph IR evidence,
but admission and Graph presence grant no authority and execute nothing. A
trusted in-process extension still needs an exact application-owned
implementation and an explicit decision for every declared capability request.
That decision must become inspectable typed wiring without introducing ambient
providers, runtime service location, discovery, or a claim of sandboxing.

## Decision

Create Experimental `kongono/extension-composition` as a build-only package.
It depends only on API Metadata, Diagnostics, Extension Contract, Extension
Build, Extension Admission, and PHP.

One `ExtensionGrantPlan` binds an exact Phase 12D admission identity to a
canonical implementation list and canonical complete decision list. Every
admitted extension has exactly one application-supplied class. Every declared
request has exactly one exact grant or denial decision. Required requests are
granted; optional requests may be explicitly denied. Missing, extra, stale,
mixed, duplicate, wrong-purpose, wrong-requirement, wrong-version, or ambiguous
state fails closed.

A grant authorizes only one exact supplied provider object to cross one exact
generated constructor parameter. It creates no Principal, Security Permit,
bearer token, ambient authority, or transitive grant. Application extensions may
receive only application-lifetime providers. Operation extensions may receive
application- or operation-lifetime providers. A denied optional parameter must
have a declared default and is omitted from the named constructor call.

Build-time Reflection validates only the exact supplied implementation and
provider contract symbols. It performs no scan, discovery, alias or case repair,
autowiring, inference, or provider instantiation. Output is canonical ordinary
PHP containing exactly typed application and operation assemblies, explicit
`new` expressions, named arguments, and typed positional accessors.

Generated bytes are inert derived evidence. Structural and caller-relative
exact-current validation never load or execute them. Optional publication uses
only the wiring SHA-256 filename in one explicit existing safe directory and is
atomic, idempotent for identical content, and no-clobber for conflicts.

Trusted in-process PHP remains honestly non-sandboxed. Capability providers
restrict only Kongono-supplied collaboration edges, not arbitrary process access.

## Consequences

- Declaration, admission, grant, generated evidence, and future execution stay
  distinct.
- Applications explicitly own implementation selection, decisions, provider
  contracts, provider objects, and publication destinations.
- Generated application state retains only application providers needed by
  later operation construction; operation providers and instances are never
  retained there.
- Deterministic identities invalidate stale or mixed inputs without timestamps,
  randomness, environment, working directory, or process state.
- The package graph becomes 61 packages and 217 acyclic local production edges.

## Rejected alternatives

- Runtime scanning, Reflection discovery, attributes, Composer probing, or
  newest-file selection.
- Ambient containers, mutable registries, resolver injection, hidden autowiring,
  property-hook acquisition, or generic provider maps.
- Default, wildcard, ranged, inherited, or transitive capability grants.
- Reusing or merging the general Composition source or its internal emitter.
- Treating trusted PHP capability ports as a sandbox.
- Loading or executing generated wiring during Phase 12E validation.

## Deferred work

Phase 12F may define a bounded trusted in-process Extension Host lifecycle,
cleanup, isolation, and failure preservation under separate authenticated
authority. Phase 12E adds none of that behavior.
