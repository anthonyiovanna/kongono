# ADR 0091: Deterministic Generated Persistence State Evidence

- Status: Accepted
- Date: 2026-08-25
- Phase: 7D

## Context

Phase 7C compiles exact-current persistence intent into a detached canonical
model and provenance artifact. That evidence proves what an application has
declared, but it does not yet prove that the declaration can become typed PHP
which preserves application construction and accessor contracts.

Runtime Reflection, proxy generation, private-state mutation, and dynamic
mapping would move correctness-critical decisions into production execution.
They would also hide stale inputs and make behavior depend on ambient autoload,
scanning, mutable registries, or runtime code generation.

## Decision

Accept deterministic generation of ordinary PHP state-adapter evidence from one
exact-current Phase 7C persistence artifact. Generation first validates every
explicit current input, consumes only the detached validated model, binds the
reviewed builder and generator implementation identities, emits canonical PHP,
enforces the fixed byte bound, and structurally validates the result without
executing it.

Each entity receives one final, non-instantiable state adapter. Its public static
API is exactly `hydrate`, `extract`, `identity`, `snapshot`, `changes`,
`insertion`, and `deletion`. Hydration invokes only the application's declared
public constructor or named factory. Extraction invokes only declared public
accessors. Generated code does not use Reflection, serialization bypass,
uninitialized objects, proxies, dynamic properties, or private-state access.
Application construction and accessor exceptions propagate unchanged.

The generated namespace appends `Artifact_` and the first 32 hexadecimal
characters of the current persistence-artifact SHA-256. The publication filename
is the full generated-PHP SHA-256 plus `.php`. These content addresses prevent
newest-file selection, mixed evidence, and ambiguous replacement while allowing
multiple exact artifacts to coexist.

Snapshots are detached typed field-shape evidence. Change sets compare one
explicit snapshot with current accessor output and produce neutral Phase 7B
change records. They do not track objects, perform I/O, flush, own transactions,
resolve relationships, or implement a unit of work.

Structural validation is non-executing and fail closed. It proves canonical
bytes, the exact provenance header, namespace, class map, declarations, methods,
and a closed token/function grammar. Exact-current validation separately
regenerates from the supplied current source, mapping, domain, Composer, builder,
and generator inputs and requires byte identity. Syntax-valid but unexpected
top-level executable statements are rejected without execution.

Publication remains explicit, content-addressed, atomic, idempotent for identical
bytes, initial-only, and no-clobber. The caller supplies an already existing
application-owned output root. The fixed target basename is
`kongono-persistence-state-v1-<generated-file-sha256>.php`; traversal, alternate
streams, links, junctions, reparse points, aliases, and destination escape fail
closed.

## Type and identity consequences

- Boolean, integer, finite float, UTF-8 text, and binary field values retain
  their declared scalar type and nullability at hydration, extraction, and
  snapshot boundaries.
- Identity and concurrency values use disjoint tagged encodings. Floats use a
  deterministic big-endian binary representation; text and binary use distinct
  tags even when their bytes are equal.
- Non-finite floats, invalid UTF-8 text, wrong record keys, wrong scalar types,
  oversized encoded values, and malformed snapshots fail with fixed
  non-disclosing generated-state diagnostics.
- Generated bytes and generated output are derived evidence, never governing
  authority and never checked into the repository by this phase.

## Security and file safety

Generated PHP is untrusted until both structural and exact-current validation
pass. Validation tokenizes and parses without loading the file, rejects
executable top-level syntax and dangerous language capabilities, and never
executes attacker-supplied bytes. Diagnostic messages and Safe context exclude
entity, record, snapshot, identity, concurrency, source, path, generated-byte,
and application-exception values.

External proof may load only a freshly emitted file outside the repository after
lint, maximum static analysis, configured style, structural validation, and
exact-current validation pass. Temporary files must be removed after proof.

## Deferred capabilities

Phase 7D adds no runtime loader or autoload registration, command, checked-in
application output, persistence context, identity map, unit of work, flush,
dirty tracker, repository, database/SQL/session/transaction behavior,
relationship loading, cascade, proxy, lazy loading, Composition integration,
deployment behavior, or provider selection. Phase 7E remains planned and has
not begun.
