# ADR 0084: Compile-Time Data Mapping and Generated Repositories

- **Status:** Accepted
- **Decision type:** Phase 6F implementation boundary
- **Stability:** Experimental APIs, source format, artifacts, and generated output

## Context

Kongono has explicit database execution, immutable SQL plans, and deterministic
schema migrations. Applications still need a bounded way to translate database
rows into typed application records without making runtime reflection,
discovery, service location, proxies, or an ORM authoritative.

## Decision

An application may explicitly select one inert relative
`kongono.data-mapping.json` source beneath its own root. Version 1 is a closed,
bounded vocabulary of generated namespace, record mappings, fields, table
identities, one assigned identity, exact scalar kinds, nullability, constructor
parameters, and accessors. Unknown members, aliases, traversal, links, unstable
reads, duplicate JSON members, and unsupported shapes fail closed.

Each mapped record must already exist and be a final readonly class. Its public
constructor and public zero-argument accessors must match field order and exact
native `bool`, `int`, `float`, `string`, or nullable scalar signatures. This
contract is inspected with Reflection only during the explicit build/check
step. The generated runtime PHP contains no Reflection, scanning, inference, or
source-file access.

The builder detaches a canonical semantic model from source bytes. Canonical
mapping order is record-ordinal, field order remains declared order, and raw
source identity remains separate from semantic model identity. The mapping
artifact binds the exact source path and bytes, `composer.json`, `composer.lock`,
the declaring record files, the canonical model, and the builder implementation.
Current validation recaptures all evidence and fails on stale, mixed, missing,
malformed, or unverifiable state.

The generator emits one final mapper and one final repository per mapping under
the exact declared namespace. Generated bytes carry exact artifact, model, and
generator identities. Mappers hydrate fixed `kgn_fNNNN` aliases in constructor
order and extract each accessor exactly once. They enforce exact row shape,
value kind, nullability, native type, and finite floats.

Repositories expose only `find`, `insert`, `update`, and `delete`. The identity
type is the mapping's assigned non-null integer or text type. Each repository is
constructed with caller-owned `DatabaseExecutor` and `SqlDialectCompiler`
capabilities. It creates bounded immutable plans, compiles and executes each
once, and returns transparent `CommandResult` evidence for mutations. `find`
selects the exact mapped projections with limit two, returns null or one record,
rejects two rows, and closes its stream exactly once.

Repositories do not create, retain beyond construction, close, retry, or
replace the caller's executor, session, transaction, or compiler. A find
failure remains primary; close failures retain the primary throwable and exact
cleanup throwable order. Diagnostics `KGN-MAPPING-1001` through `1009` expose
only package-owned bounded structural evidence and never rejected source text,
record values, SQL, parameters, credentials, provider details, paths, or
topology.

Generated validation tokenizes PHP without executing it and current validation
regenerates exact bytes. Publication is content-addressed, atomic, idempotent,
initial-only, and no-clobber. Generated PHP and mapping artifacts are derived
evidence, never source authority, and are not checked into this repository.

## Security and persistent-runtime implications

Mapping source is untrusted inert data and cannot expand tool or runtime
authority. Generated namespace and class names are validated before loading;
the framework package itself does not provide a production loader. Applications
must load only exact current validated bytes through an explicit application
build/runtime boundary. Generated repositories are stateless apart from their
caller-owned capabilities, so persistent runtimes do not acquire an ambient
session, identity map, cache, or mutable unit of work.

Concurrent builds may target the same content identity safely; conflicting
bytes fail rather than overwrite. Concurrent repository calls remain governed
by the supplied executor's lifecycle and concurrency contract. The mapping
package adds no stronger guarantee.

## Evidence

Focused tests prove source and record bounds, canonical identity, provenance,
staleness, generation, non-executing validation, publication, exact hydration
and extraction, plan construction, failure composition, nondisclosure, and
prohibited-feature absence. Fresh emitted PHP passes lint, maximum PHPStan, and
cache-disabled style outside the repository. The root-owned PostgreSQL 17.2
harness proves generated CRUD, all scalar kinds, nullability, both identity
kinds, cardinality rejection, caller transaction rollback and reuse,
independent repositories, deterministic failures, and complete temporary
cleanup.

## Consequences

Applications gain readable typed Data Mapper and repository output while raw
parameter-bound statements and immutable SQL plans remain first-class. Build
inputs and generated identities are explicit and reviewable. Applications must
own their record classes, mapping source, build invocation, exact generated-file
loading, executor/compiler selection, transactions, and lifecycle.

Build-time reflection, hashing, canonicalization, generation, and validation
have bounded cost proportional to the declared source and record files. Runtime
mapping avoids reflection but still performs explicit value checks, allocation,
plan construction, compilation, execution, and stream cleanup. No zero-overhead
claim is made.

## Rejected alternatives

- Runtime Reflection, attributes, scanning, convention, or inference as mapping authority.
- Dynamic proxies, generated code mutation, `eval`, or hidden lazy loading.
- A base model, Active Record, identity map, unit of work, dirty tracking, or entity manager.
- Automatic relations, cascades, joins, custom queries, query derivation, or pagination.
- Ambient sessions, container injection, automatic transactions, retry, migration, or schema behavior.
- Checked-in generated artifacts or overwriting publication.
- Provider-specific mapping or coupling mapping to composition/runtime loading.

## Non-goals

This decision adds no ORM, relation model, collection semantics, generated
identity, hooks, validation, serialization, domain conversion, production
loader, composition integration, skeleton, command, deployment behavior,
another database dialect, Stable API, 1.0 claim, production-readiness claim,
universal portability claim, or Phase 6G behavior.
