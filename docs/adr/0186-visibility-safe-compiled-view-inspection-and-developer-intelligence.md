# ADR 0186: Visibility-Safe Compiled-View Inspection and Developer Intelligence

- Status: Accepted
- Date: 2026-09-13
- Phase: 18G only

## Context

Phase 18F accepted one exact-current compiled-view application profile over the
neutral contract, deterministic build, bounded runtime, and explicit HTTP
adaptation boundaries. Developer intelligence needs bounded evidence about one
such supplied profile without reading application files, loading generated PHP,
rendering a view, disclosing presentation material, or claiming live deployment
truth.

## Decision

Add the optional Experimental `kongono/view-inspection` upper evidence leaf. It
depends exactly on `kongono/api-metadata`,
`kongono/application-graph-intelligence`, `kongono/diagnostics`,
`kongono/observability`, `kongono/security-audit`, `kongono/view-application`,
`kongono/view-build`, and `kongono/view-contract`.

One `ViewInspectionRequest` carries exactly one already exact-current
`ViewApplicationProfile`. The inspector structurally revalidates the supplied
in-memory artifact metadata and generated bytes through the accepted Phase 18C
validator. It compares the reconstructed artifact and checks profile,
currentness, source, compiled, model, generated, and view-count bindings. It
performs no filesystem access, source read, generated-code load or execution,
reflection, rendering, HTTP adaptation, or production observation. Supplied
exact-current evidence remains caller-relative evidence, not proof of current
live filesystem or deployment state.

The canonical version-1 schema is `kongono.view-inspection`. Its identity is
lowercase SHA-256 over fixed-order canonical UTF-8 JSON excluding only the
identity field. Output is restricted to declared Safe fixed vocabulary and
bounded aggregates plus Protected digest bindings. Paths, basenames, templates,
contexts, values, schemas, source or generated bytes, rendered bytes, class
names, HTTP material, foreign failures, arbitrary caller content, and traces are
omitted.

Chie, Hantei, and Oshie identifiers map exactly to explain, verify, and teach
evidence purposes. No role is imported, invoked, impersonated, or granted
authority. The independent verifier reconstructs the permitted view shape
without calling the deriver; mismatched fields, order, role, limitations,
bindings, aggregates, or markers fail closed without normalization or repair.

Graph evidence is optional and must use the same role. Only permitted Safe
aggregate counts and fixed vocabulary cross that boundary. The compiled-view-
to-Graph relationship is always `not-established`. Observability and Security
Audit projections construct neutral in-memory evidence marked
`constructed-not-recorded`; they do not record, export, persist, sample, flush,
or certify anything.

Diagnostics `KGN-VIEW-INSPECTION-1860` through `1864` cover invalid inspection,
artifact evidence, profile or binding mismatch, invalid intelligence or
verification evidence, and projection failure. Diagnostics are bounded and
nondisclosing and preserve translated prior throwable identity.

## Security and lifecycle

The package is synchronous, deterministic, offline, read-only, stateless, and
retains no cross-call state. It performs no filesystem, environment, process,
network, clock, randomness, source execution, generated-code execution,
rendering, application execution, authority evaluation, replay, repair,
recording, exporting, certification, or role execution. Digests are comparison
evidence, not secrets, authentication, authorization, non-repudiation, Graph
relationships, or external truth.

## Consequences

- Phase 18A-G are Accepted; Phase 18H remains Planned and separately
  unauthorized.
- The graph contains 95 acyclic production packages and 402 local production
  dependency edges; PHP inventories are 1,861 production, 962 package-test,
  and 92 root-test files.
- Applications gain bounded visibility over one explicit supplied profile, not
  monitoring, live-currentness, security, performance, browser, deployment, or
  production-readiness evidence.
- No command, recorder, exporter, cache, watcher, daemon, Stable/1.0 surface,
  checkpoint, certification, or Phase 18H behavior is added.

## Alternatives considered

1. Inspecting the artifact directory again - rejected because the inspection
   boundary accepts supplied evidence and performs no I/O.
2. Loading generated PHP to confirm its class - rejected because structural
   validation must remain inert and non-executing.
3. Reusing the deriver inside the verifier - rejected because verification must
   provide an independent comparison path.
4. Treating Graph projection as a relationship - rejected because copied
   aggregate evidence establishes no Graph fact.
