# Extension Capability Grants and Generated Wiring

Phase 12H externally proves explicit grant/deny planning and deterministic
ordinary PHP generation without changing this build boundary. A request is not
a grant, generated bytes are inert before the explicit host load, and provider
edges do not sandbox trusted PHP. See
[Phase 12 external acceptance](phase-12-external-acceptance.md).

## Purpose and current boundary

Phase 12E implements Experimental `kongono/extension-composition`. It converts
one exact Phase 12D admission result plus explicit application-owned
implementation and capability decisions into deterministic typed PHP evidence.
It is build-only: no generated file is loaded or executed.

## Inputs and exact binding

Generation receives the complete canonical Phase 12B declaration list, the
exact Phase 12D `AdmittedExtensionGraphInput`, and one `ExtensionGrantPlan`.
The declaration identity is rebuilt with Phase 12C behavior. The admission and
plan identities must match exactly. Each admitted extension must be
`TrustedInProcess`, have one exact implementation class, and match one current
declaration identity and version.

Every capability request has exactly one decision with the same extension,
capability identity/version, purpose, requirement, constructor parameter, and
provider contract. Required denial fails. Optional denial is valid only for a
matching non-nullable typed parameter with a declared default.

## Capability meaning and provider lifetime

A grant means only that generated wiring may receive one exact object satisfying
the named contract and pass it into the named constructor parameter. It is not
authorization, a Principal, a Security Permit, a token, or permission to any
other resource.

Application-lifecycle extensions accept only application providers. Operation
extensions may accept application and operation providers. Application
providers needed for an operation extension are retained by the application
assembly for typed forwarding. Operation providers and operation extension
instances remain operation-local.

## Build-time validation

Reflection is restricted to the exact supplied implementation class and
provider contracts already available through normal application autoloading.
Implementations must be exact-case userland instantiable named classes with a
public non-static constructor or no constructor. Parameters must be exact
non-nullable named userland class/interface types and may not be promoted,
variadic, by-reference, hidden, inferred, or unrepresented.

There is no directory, package, attribute, or Reflection discovery; no alias or
case repair; and no autowiring, fallback, or provider instantiation.

## Generated evidence

The canonical UTF-8/LF PHP file uses a content-bound namespace under
`KongonoGenerated\Extension\V1`. It contains exactly final
`ExtensionApplicationAssembly` and `ExtensionOperationAssembly` classes.
Application providers enter `start()`, operation providers enter
`beginOperation()`, extensions are constructed with explicit `new` expressions
and named arguments, and positional typed accessors preserve admitted order.
Denied optional arguments are omitted so PHP owns their declared defaults.

The output contains no container, resolver, registry, generic lookup, variable
class, Reflection, autowiring, include, require, eval, callback, lifecycle loop,
or cleanup behavior. Tests parse and lint generated bytes but never load them.

## Artifact and publication

`GeneratedExtensionWiringArtifact` preserves complete bytes and SHA-256 plus
declaration, admission, plan, generator, namespace, class, and bounded count
evidence. Structural validation is non-executing; exact-current validation
regenerates from the caller's complete current inputs. Publication writes only
`<wiring-sha256>.php` in an explicit existing safe directory, atomically and
without clobbering conflicting bytes.

## Security and lifecycle truth

Trusted in-process PHP has the full technical power of its process and is not
sandboxed by these provider edges. Phase 12E itself grants no host, execution,
startup, shutdown, cleanup, retry, Graph, Security, CLI, marketplace,
developer-intelligence, or operational authority. Phase 12F now adds lower
generated hosted boundaries and a separate bounded host lifecycle while
preserving the typed wiring and exact implementation identity. See the
[Trusted In-Process Extension Host](trusted-in-process-extension-host.md).
