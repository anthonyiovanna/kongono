# Phase 22 Local Application Events Acceptance

Phase 22F supplies a root-owned local acceptance runner for the separately
optional Experimental event contract and synchronous runtime. It exercises
the accepted application-owned copy-once example through a separate process
and a new private Composer installation with its own autoloader. The source
packages are the four authenticated local packages from the same Kongono
checkout. This is independently composed consumer evidence for that source
state, not a published distribution or independent human certification.
The runner consists of [the entry point](../../tests/External/ApplicationEvents/run.php),
[the eight-group harness](../../tests/External/ApplicationEvents/Phase22ApplicationEventsAcceptance.php),
[process results](../../tests/External/ApplicationEvents/ProcessResult.php), and
[private workspace ownership](../../tests/External/ApplicationEvents/TemporaryEventWorkspace.php).

## Running the bounded local proof

The root `acceptance:phase22` script invokes
`tests/External/ApplicationEvents/run.php` with 512M PHP memory. A controlled
runner must supply an authenticated PHP 8.5.11 profile, offline child-only
environment, `KONGONO_PHASE22F_COMPOSER_PHAR` naming the authenticated
ordinary Composer PHAR, and `KONGONO_PHASE22F_EVIDENCE_ROOT` naming one absent
private GUID directory directly beneath its private temporary directory.
The harness rejects missing or unknown arguments and invalid tool or output
locations before consumer effects. It never chooses system Composer or
enables Packagist. Successful output is one bounded JSON object with schema
`kongono.phase-22-application-events-acceptance`, profile
`application-events-local/1`, and these eight closed check names:

| Check | Evidence |
| --- | --- |
| `loading-registration` | Explicit class loading, inert validated registration, duplicate and malformed rejection before effects. |
| `exact-delivery` | Exact concrete type, ordered matching and the same event object. |
| `idle-native` | Empty and unmatched success plus native wrong-type rejection. |
| `authorization` | Strict current application authorization before each receipt and ledger effect, with truthful earlier progress. |
| `throwable-progress` | Original `Exception` and `Error` identity, earlier effect retained and later effect absent. |
| `reentry-isolation-repeat` | Caught and escaping nested rejection, guard release, separate instances and deliberate repeat. |
| `safe-presentation` | Fixed Safe diagnostic summaries under both trace-argument modes, without claiming native or handler output sanitization. |
| `copied-consumer` | Eight exact copied paths, four local dependencies, copied installation, own autoload, fixed demo and missing-bootstrap output, caller error-handler restoration. |

The copied application contains exactly the eight paths in
`skeletons/event-minimal/kongono.skeleton.json` before its private repository
rewrite. The original copied lock is retained as evidence. Only the private
`composer.json` repositories change: Packagist is disabled and four absolute
local path repositories use copied files rather than symlinks. One offline
update, install and validation each produce private generated lock, vendor
and cache evidence. The consumer demo uses only its own vendor autoloader.
The runner does not copy to a user's application destination or change the
repository's root/example lock or vendor trees.

The harness keeps raw stdout, stderr, indexed argv, child results, generated
scripts, copied source, generated lock and installed files under its owned
private evidence root. Child processes have fixed limits and must retire;
a timeout, output overflow, native crash, uncertain retirement or network
demand is a failed infrastructure gate, not a case to silently retry. The
runner emits only fixed failure text publicly. Private captures may contain
paths or native output and must not be presented as Safe diagnostics.

## Authority and limits

Phase 22A–E are architect-accepted within their recorded limits. Phase 22F's
local implementation, separated broad static validation and two owner-context
full-suite profiles have passed within the recorded scope. Phase 22F.47 accepts
the explicit F.9 separated validation set as satisfying the corresponding
offline broad-validation requirement; literal composer quality and
composer hantei:verify were not run and are not claimed as passing.
The September 30, 2026 locked audit is retained for the unchanged lock.
Fresh documentation and offline Knowledge results are recorded in the
[final Phase 22F report](../task_reports/phase_22/Phase_22F.md), populated only
after the successful fresh check and preservation proof. Architect milestone
review and the exact checkpoint remain pending. Phase 22 is not closed.
A successful local
runner cannot accept itself, prove third-party distribution, or establish
production readiness. No Phase 23 work is authorized by this evidence.

The example's policy and effects are application-owned in-memory code, not
production authorization. Each effectful handler must check its actual
application policy immediately before its effect. The first original handler
`Throwable` escapes unchanged; earlier effects remain and later handlers
do not run. Dispatch grants no transaction, rollback, retry, durable or
exactly-once delivery claim. The narrow demo `E_WARNING` conversion covers
its trusted autoloader require and restores the previous error handler in
`finally`; it does not sanitize arbitrary PHP, handler output or traces.
No queue, worker, broker, outbox, event store, generated wiring, Graph fact,
AI or telemetry integration is part of this local acceptance. PHP support
remains `>=8.5.0 <8.6.0`.
