# Phase 6 External Data Platform Acceptance

## Purpose and status

Phase 6H supplies the root-owned, test-only whole-platform proof for the
accepted eight-package Data Platform. Run the exact local PostgreSQL profile:

```text
composer acceptance:phase6 -- "C:\laragon\bin\postgresql\postgresql-17.2-3-windows-x64-binaries\bin"
```

Success is one canonical single-line JSON object followed by one LF and empty
stderr. The accepted fields are `status`, `profile`, `server_major`,
`case_count`, `cleanup`, and `performance`, in that order. `case_count` never
drops below the previously accepted 140 cases, and `cleanup` becomes
`complete` only after all owned process and filesystem state is gone.

## Boundary exercised

The harness proves the one-way package chain from neutral statements, values,
sessions, results, and transactions through the PostgreSQL PDO adapter,
immutable SQL plans and PostgreSQL 17 compiler, deterministic migration catalog
and executor, compile-time mapping and generated typed repositories, and the
outer generated data-application lifecycle. It also installs a fresh copied
`skeletons/data-minimal` application offline, builds mapping before composition,
checks exact-current output without mutation, and starts it with an explicit
host-supplied connector.

Fresh sessions own independent temporary relations. Overlapping read-committed
sessions observe no uncommitted insert, observe it after commit, and never
observe a rolled-back insert. Sequential and overlapping generated operations
receive distinct session, root, and repository identities while their
application-lifetime stateless compiler is shared. Transaction terminals are
one-attempt boundaries with no implicit retry, and failure in one session does
not retire its peer.

Migration evidence covers ordering, current-state no-op, destructive review,
rollback, exact-history mismatch, prefix isolation, lock contention, and
reserved-history cleanup. Missing, stale, renamed, crossed, changed, or
tampered mapping, generated data-access, composition, or generated-wiring state
fails closed without scan, newest-file, or fallback selection.

## Ownership and cleanup

Each run creates a private system-temporary root, initializes and starts its own
PostgreSQL 17 cluster, creates only its bounded role/database state, and uses an
owned loopback port. The repository is read-only to the harness. Copied package
mirrors, application vendor files, generated output, provider data, processes,
ports, and the entire temporary root are removed in `finally` before success.

Failure emits one bounded public token and no success JSON. Exceptions, string
forms, subprocess streams, and JSON exclude passwords, usernames, hosts,
ports/DSNs, database and record values, SQL and parameters, migration identities,
source/generated bytes, absolute paths, provider messages, and stack arguments.

## Measurement evidence

The `performance` member follows the version-1 protocol documented in the
[database performance baseline](../engineering/database-performance-baseline.md).
It contains environment-neutral protocol metadata and four ordered summaries,
not raw samples. The figures are local observations rather than thresholds or
cross-machine comparisons.

## Limits

This proof adds no production database service, runtime telemetry, connection
pool, retry, ambient credential source, schema auto-sync, ORM, Active Record,
relations, identity map, unit of work, proxy, hidden lazy I/O, deployment
behavior, or further provider. APIs remain pre-1.0 and Experimental.
