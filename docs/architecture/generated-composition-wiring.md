# Generated Composition Wiring

## Current boundary

Phase 5E extends the Experimental `kongono/composition` package with a build API
that turns one exact current Phase 5D artifact into one canonical typed PHP
file. The generated file is derived build evidence. Production loading and
application integration remain planned for Phase 5F.

The public build types are `GeneratedWiringArtifact`,
`GeneratedWiringGenerator`, `GeneratedWiringValidator`, and
`GeneratedWiringPublisher`. `GeneratedApplicationBoundary` and
`GeneratedOperationBoundary` expose only operation creation, shutdown/close,
and state. They provide no service or root lookup by string or class name.

## Source-to-code path

```text
application-owned JSON
  -> current Composition artifact
  -> generated-wiring generator
  -> canonical PHP plus bound metadata
  -> non-executing structural/current validation
  -> optional explicit content-addressed publication
```

Generation reads the canonical model from the validated artifact. It does not
reread constructors during emission. One output namespace binds the exact
Composition artifact SHA-256 and contains exactly `ApplicationAssembly` and
`OperationAssembly`. The artifact separately exposes complete PHP bytes, wiring
SHA-256, Composition/model/generator identities, namespace, and class names.

## Explicit aggregate services

Version 1 accepts only a single `service`, typed `input`, or `default: true` for
each constructor parameter. A host application that wants multiple handlers
declares its own concrete aggregate, for example `HandlerCollection(HandlerA
$first, HandlerB $second)`, then injects that aggregate by its exact contract.
The two constructor edges and their order are explicit in the source and
generated named calls.

Kongono does not provide collection injection, automatic multibinding, tags,
priorities, discovery, a framework aggregate type, array/iterable widening,
variadics, or PHPDoc collection semantics.

## Runtime-support behavior

`ApplicationAssembly::start()` receives one explicitly typed parameter for
each input and eagerly constructs application roots. `beginOperation()` eagerly
constructs operation roots and returns a new isolated operation. Application
services share within that application; operation services share only within
one operation; each transient edge receives a fresh instance. Default arguments
are omitted from calls so PHP owns their declared value.

Cleanup is registered immediately after each successful owned construction and
runs once in strict reverse order. Partial construction cleans prior instances.
An operation holds one lease, so application shutdown cannot begin while an
operation is active. A close/shutdown attempt permanently closes/retires its
boundary once cleanup begins, including on failure; repeats do nothing.

Failure composition preserves exact Throwable objects without exposing their
messages through Composition diagnostics. `KGN-COMPOSITION-1013` through
`1016` cover invalid wiring, publication failure, combined lifecycle failures,
and unavailable retired/closed boundaries.

## Security and calling contract

Generate only from an exact current artifact and validate before any test-only
load or explicit publication. Runtime inputs pass directly into typed code and
are absent from generated bytes and metadata. Generated code uses no container,
resolver, dynamic service lookup, reflection, scanner, autowiring, runtime
include selection, variable class, global registry, or ambient state.

The application owns aggregate behavior and concurrency safety of shared
application services. Direct `OperationAssembly` construction is unsupported;
call `beginOperation()`. Close every operation before shutdown. After close or
retirement, do not access roots or begin more operations.

## Phase 5F loading boundary

Phase 5F adds the explicit `GeneratedWiringLoader` and one-use
`LoadedGeneratedWiring` boundary described in [ADR 0074](../adr/0074-generated-assembly-web-runtime-integration.md).
The caller selects one exact contained content-addressed file; exact current
validation and stable reverification occur before local execution. Startup-only
reflection checks the exact generated classes, input types, and supported web
root shape. It does not add scanning, a latest pointer, rebuilding, generated
autoloading, service lookup, or request-time reflection.

## Deliberate exclusions

Phase 5F adds only the loader and exact existing-web integration. Phase 5G
adds one copy-once application template and application-owned build/check/run
scripts over the reusable workflow. Neither phase adds a latest pointer, job
integration, Graph/DI integration, deployment behavior, or OPcache/preload
policy.
