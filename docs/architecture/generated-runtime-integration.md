# Generated Runtime Integration

Phase 5F supplies one fail-closed path from an exact current generated assembly
to the existing web lifecycle. It is an Experimental startup boundary, not a
general runtime container.

## Calling contract

The caller provides the resolved application root, exact current Composition
artifact bytes, one exact generated-file path, and ordered typed startup input
objects. The file must be the ordinary contained content-addressed file named
`kongono-wiring-v1-<wiring-sha256>.php`. Loading fails visibly on missing,
stale, tampered, truncated, mixed, oversized, renamed, aliased, linked,
reparsed, streamed, unreadable, changed, or already-loaded evidence.

Validation and stable-snapshot reverification complete before the one local
`require`. The loader neither searches nor repairs. A loaded boundary can start
once; an input count, order, or native type mismatch fails before generated
construction. The generated boundary retains authority for construction,
partial cleanup, reverse cleanup, and exact failure composition.

## Exact web shape

The supported profile is:

```text
Generated application assembly
  -> one GeneratedWebRuntimeRoot application root
     -> one WebApplication
     -> one GeneratedWebRuntimeBootstrap
  -> no generated operation roots
```

Startup-only reflection verifies that exact shape and exact return type. It
does not inspect constructors, discover services, or execute during a request.
`GeneratedWebRuntimeApplication` retains the generated boundary and typed root.
It exposes no arbitrary root, service, input, resolver, registry, or container
lookup.

## Exact Security Runtime shape

Phase 9E adds a separate outer profile over the same exact-current loader:

```text
Generated application assembly
  -> no application root
  -> exactly one SecurityContext operation input
  -> exactly one SecurityOperationRoot operation root
```

`GeneratedSecurityApplication` completes bounded profile reflection before
generated startup. Each explicit anonymous or authenticated entry constructs a
fresh context and calls `beginOperationWithInputs()`. Operation entry performs
no reflection or lookup, and generated application state retains no context.
This profile performs no authorization or protected-capability enforcement.

## Request and shutdown path

```text
CgiGeneratedFrontController
  -> CgiFrontController
     -> CgiWebEntry
        -> WebRuntimeAdapter: one send and one close
           -> WebApplication: one Kernel operation per request
              -> RoutingRequestHandler and MiddlewarePipeline

generated shutdown
  -> generated reverse cleanup
     -> WebApplication::shutdown()
        -> Kernel::shutdown()
```

The generated web application does not begin a generated operation. Request,
response, route-match, failure, and Kernel-scope values remain in the existing
lower call frames and are not retained in generated application state. Repeated
generated shutdown is idempotent and does not retry cleanup.

## Failure and disclosure

Before generated start, profile failures use `KGN-WEB-RUNTIME-1003`. If root
access unexpectedly fails after start, generated shutdown receives that exact
primary failure so Composition's existing lifecycle composer remains
authoritative. Loader admission failures use `KGN-COMPOSITION-1017`.

Both diagnostics expose only fixed violation tokens. Raw paths, artifact or
generated bytes, runtime objects, request data, environment values, native
messages, credentials, and secrets are excluded from package-owned output.

## Deliberate exclusions

There is no directory scan, latest pointer, network access, generated autoloader,
runtime `eval`, remote/data wrapper, request-time reflection, constructor
inference, attribute scan, autowiring, service location, generated operation in
the web request path, DI/Graph integration, route-source expansion, new
transport, checked-in generated artifact, framework CLI, listener, or
deployment behavior. Phase 5G composes this existing boundary from the
copy-once skeleton without moving lifecycle ownership.
