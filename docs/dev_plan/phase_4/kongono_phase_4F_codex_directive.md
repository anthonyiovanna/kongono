## 2. Purpose and milestone boundary

Phase 4F implements the first useful, deterministic, read-only Kongono Oshie
learning slice.

The locked promise is:

> **Oshie helps you understand it.**

This phase must prove all of the following:

1. Oshie consumes the same exact current Phase 4C framework-knowledge artifact
   as the other developer-intelligence roles.
2. A developer can discover a closed curriculum, read an exact cited lesson,
   receive a closed exercise, and submit one exact answer token.
3. Exercise checking is deterministic and version-matched.
4. Every lesson, exercise, and feedback result remains visibly derived teaching
   bound to exact accepted source citations.
5. Accepted source documentation remains authoritative and independently useful
   without Oshie, AI, a provider, an account, a subscription, or a network.
6. Oshie never executes learner code, evaluates input, reads arbitrary workspace
   files, repairs code, judges framework correctness, or mutates the repository.

Phase 4F is not free-form tutoring, a chatbot, RAG, semantic search, a model or
provider integration, a course platform, user-progress persistence, an IDE
integration, code execution, an executable-example sandbox, Chie candidate
generation, Hantei verification, auto-fix, or production AI.

The v1 curriculum intentionally makes no claim that any returned prose or code
sample is executable. It contains cited reading and exact-answer knowledge
exercises only. An executable-example claim requires a separately Accepted
execution and proof boundary; do not infer one here.

## 11. Request and response contract

### 11.1 Requests

`OshieRequest` provides only:

```text
catalog()
lesson(string $lessonId)
exercise(string $exerciseId)
check(string $exerciseId, string $answerToken)
```

IDs and answer tokens use lowercase ASCII `[a-z0-9-]`, 1 through 64 bytes.
`check()` admits only a token that is one of that exercise's package-owned
options; unknown or malformed input fails safely and is never echoed.

### 11.2 Resolution

`Oshie::respondCurrent(string $frameworkRoot, string $artifactBytes,
OshieRequest $request): OshieResponse` must:

1. enforce the current Knowledge artifact bound;
2. structurally validate the supplied bytes;
3. exactly validate current source state against the explicit root;
4. load the exact package-owned curriculum;
5. resolve each referenced source exactly once;
6. admit only governing authority or current explanatory documentation;
7. extract the complete contiguous exact level-two section through the next
   unfenced level-two heading or source end;
8. preserve exact source bytes and inclusive line bounds;
9. bind every returned teaching value to an exact `kgn-source-v1` citation; and
10. produce one detached immutable response.

Unknown admitted lesson/exercise IDs return `unsupported`; no fuzzy match,
nearest result, ranking, correction, or guess is allowed.

### 11.3 Response states

Use schema `kongono.oshie-response`, version `1`, role `oshie`, and exact key
order:

```text
schema
version
role
status
operation
curriculum_id
framework_artifact_sha256
source_set_sha256
curriculum
lesson
exercise
attempt
uncertainties
```

Closed statuses:

| Operation | Successful status | Payload |
|---|---|---|
| `catalog` | `available` | six ordered lesson summaries |
| `lesson` | `taught` | one exact cited lesson |
| `exercise` | `practice` | one cited prompt and ordered options, never its accepted answer |
| `check` | `correct` or `incorrect` | one outcome, accepted answer, fixed feedback, and citations; never raw submitted input |

Artifact/source identities are present for successful and unsupported current
responses. `unavailable`, `stale`, and `blocked` carry null identities and one
closed uncertainty. Unsupported uncertainties are exactly `lesson-unsupported`
or `exercise-unsupported`. Artifact uncertainties are exactly
`artifact-unavailable`, `artifact-stale`, or `artifact-invalid`.

All arrays are lists. Values are defensively detached. Cross-field invariants
make impossible state/payload combinations unconstructable. Citations bind
reference, repository-relative path, authority, source SHA-256, and positive
inclusive line range; their reference source-set component must equal the
response source-set identity.

Canonical JSON is compact UTF-8, unescaped slashes and Unicode, one final LF,
maximum depth 32, and at most 262,144 bytes. Limit breaches fail closed; never
truncate or partially succeed.

## 14. Security, lifecycle, and performance

publication, deployment, production, application-request, or Hantei operation.

and response size. Avoid reflection-driven request-time dispatch, service
location, global mutable registries, hidden I/O, dynamic class discovery,
unbounded recursion, and speculative abstractions.
