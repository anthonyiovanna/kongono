## 8. Phase 4D architecture decision

Create and accept:

```text
ADR 0063: Read-Only Chie Explanation and Diagnostic-Observation Boundary
```

The decision is:

1. `kongono/chie` owns the read-only Chie role runtime.
2. It depends only on `kongono/api-metadata`, `kongono/diagnostics`, and
   `kongono/knowledge`, plus required PHP extensions.
3. No existing production package depends on Chie.
4. Chie consumes an explicit Phase 4C artifact and validates it against an
   explicit framework root before answering.
5. Chie never generates, publishes, repairs, replaces, or deletes a knowledge
   artifact.
6. Explanation uses six closed topic definitions and exact contiguous source
   sections. It is not free-form generation.
7. Diagnosis accepts one Safe diagnostic identifier only. It performs bounded
   literal occurrence resolution over the exact validated artifact. It reads
   no diagnostic message, stack trace, source file, environment variable, or
   arbitrary workspace content.
8. Chie output is derived material with exact citations. It never becomes
   governing authority or implementation proof by itself.
9. Unsupported, unavailable, stale, invalid, and limit states fail visibly.
10. Chie is offline and deterministic. There is no model, provider, prompt,
    embedding, vector store, general retrieval engine, network call, account,
    credential, telemetry, retention, or training.
11. Chie has no file-write, dependency, Git, staging, commit, publication,
    deployment, production, or application-runtime authority.
12. Chie cannot return `PASS`, `FAIL`, or `BLOCKED` verification verdicts and
    cannot certify its own explanation. Hantei remains Phase 4E.
13. No patch, diff, candidate change, or auto-fix exists before Phase 4G.

The new architecture document must explain the contract, data flow, schemas,
limits, citations, state handling, command behavior, threat model, and explicit
non-goals in developer-friendly language.

## 12. Request and observation contract

`ChieOperation` has exactly:

```text
Explain  = explain
Diagnose = diagnose
```

`ChieRequest` exposes named constructors:

```php
public static function explain(string $topic): self;
public static function diagnose(DiagnosticObservation $observation): self;
```

An explanation topic is at most 64 ASCII bytes and must match:

```text
^[a-z][a-z0-9-]{0,63}$
```

Syntactically admitted but unknown topics remain unsupported. Rejected input is
never repeated in an exception, response, diagnostic context, or command
output.

`DiagnosticObservation` accepts one identifier only, at most 64 ASCII bytes,
matching:

```text
^KGN-[A-Z][A-Z0-9-]{0,47}-[0-9]{4}$
```

The observation means only: the caller supplied this syntactically Safe
identifier for bounded diagnosis. It does not prove that the diagnostic
occurred, authorize reading its raw context, or make caller text framework
truth.

No request carries a prompt, prose question, file path, stack trace, exception
message, source code, diagnostic context, environment value, secret, command,
or tool instruction.

## 13. Current artifact gate

The only role entrypoint is:

```php
public function respondCurrent(
    string $frameworkRoot,
    string $artifactBytes,
    ChieRequest $request,
): ChieResponse;
```

Before resolution, call the accepted
`FrameworkKnowledgeArtifactValidator::validateStructure()` and retain the
detached artifact only long enough to classify a structurally valid stale
input. Then call `FrameworkKnowledgeArtifactValidator::validateCurrent()`
against the explicit root and bytes. Never bypass current validation and never
accept structural validation alone for a version-matched answer.

Map knowledge failures without leaking native messages or raw rejected values:

| Knowledge condition | Chie condition | Status |
|---|---|---|
| source/root unavailable or unsafe | `ArtifactUnavailableException` | `unavailable` |
| exact current-byte mismatch | `ArtifactStaleException` | `stale` |
| malformed, noncanonical, tampered, or internally invalid artifact | `InvalidArtifactException` | `blocked` |

The public service throws the typed Chie exception. The command renders the
corresponding visible Chie status. Preserve the native cause internally only.

An invalid, stale, unavailable, or unsupported artifact never falls back to an
older artifact, a different root, an embedded answer, a cache, or a network.

1. resolve the exact catalog record;
2. resolve its exact source from the validated artifact;
3. require its authority to be Governing Authority or Current Explanatory
   Documentation as specified by the artifact;
4. locate the exact heading once;
5. return the contiguous source bytes beginning at that heading and ending
   immediately before the next LF-delimited `## ` heading or at source EOF;
6. preserve the excerpt bytes exactly; do not paraphrase, complete, summarize,
   translate, or interpret them; and
7. attach one exact citation with source reference, source path, authority,
   source SHA-256, and one-based inclusive line range.

The explanation claim class is `accepted-framework-fact` only because it is an
exact excerpt from a version-matched accepted source. Chie's response remains
derived material and cannot replace that source.

Headings inside fenced blocks or deeper headings do not terminate the section.
The extractor is deliberately a bounded line scanner, not a general Markdown
renderer or executable parser.

## 15. Diagnostic-observation resolution

For a diagnostic observation:

1. scan the validated artifact's sources in artifact ordinal order;
2. scan LF-delimited lines in one-based line order;
3. use literal, case-sensitive identifier matching, not regex constructed from
   input;
4. require token boundaries so a shorter identifier cannot match a longer one;
5. retain only exact lines containing the admitted identifier;
6. attach one exact citation to each result; and
7. preserve result order by source ordinal and line number.

After at least one exact occurrence is found, the first claim records a fixed
Current Workspace Observation statement:

```text
The caller supplied one Safe diagnostic identifier for read-only diagnosis.
```

It has no citation and does not claim runtime occurrence. Each located line is
an `accepted-framework-fact` claim with its exact citation.

If no exact occurrence exists, return `unsupported`, no claims, and closed
uncertainty token `diagnostic-not-found`. Do not guess a package, nearest
identifier, message, cause, or remediation.

This is the entire Phase 4D workspace-diagnosis boundary. There is no workspace
filesystem reader, recursive scan, Composer execution, PHP execution, log
reader, exception ingestion, diagnostic-context ingestion, retention, or
cross-project state.

## 16. Claims, citations, response states, and schema


```text

unsupported

stale
blocked
```

`ChieCitation` carries, in this order:

```text

```

It never carries an absolute path, host path, branch, mutable tag, URL, or
uncited prose.

```text

```

```text
schema:  kongono.chie-response
version: 1
role:    chie
```

Each claim key order is:

```text
class, text, citations
```

tokens. Answered responses have no uncertainty. Non-answered states never
invent claims.

insignificant whitespace, exact insertion order, and exactly one final LF.

lowercase exact digests from the successfully current-validated artifact. For
`unavailable`, `stale`, and `blocked`, both digest fields are `null`, claims are
empty, and exactly one closed uncertainty token states the condition:

```text
artifact-unavailable
artifact-stale
artifact-invalid
```

`answered` has no uncertainty. Unsupported explanation uses
`topic-unsupported`; unsupported diagnosis uses `diagnostic-not-found`.
