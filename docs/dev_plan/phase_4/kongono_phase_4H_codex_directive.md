## 2. Purpose and final Phase 4 boundary

Phase 4H is the final fixed Phase 4 subphase. It adds no framework production
capability.

It must:

1. create a root-owned, test-only external acceptance harness that exercises
   the real Knowledge, Chie, Hantei, and Oshie process boundaries;
2. prove that all roles bind to one exact current source/artifact identity;
3. prove deterministic success, unavailable, denied, stale, malicious-input,
   disclosure, and evidence-failure behavior;
4. prove accepted documentation remains independently readable without any
   developer-intelligence role, AI, provider, account, subscription, or
   network;
5. prove Chie proposals remain unapplied candidates and Hantei never certifies
   an unapplied candidate;
6. reconcile current documentation and the Phase 4 roadmap;
7. run all pre-checkpoint gates;
8. stage the exact accumulated Phase 4 path set and create one local checkpoint
   commit; and
9. rerun all mandatory post-commit gates before populating the external report.

Phase 4H does not add AI/model/provider integration, free-form prompting,
auto-fix, candidate application, production access, deployment, a new package,
a runtime API, or a release. Completion means the bounded Phase 4 developer-
intelligence foundation is checkpointed; Kongono remains pre-1.0 and not
production-ready.
