# Database Application Workflow

## Use when

Use the Experimental workflow for an application that opts into the exact
version-1 mapping source and generated Composition wiring. Keep using the lower
neutral Database and SQL contracts directly when generated repositories or the
supported composition profile are unnecessary.

## Build and check

The application supplies three explicit values: its root, the relative mapping
source path, and an already-existing strictly contained output directory.

```php
$workflow = new DataApplicationBuildWorkflow();
$current = $workflow->build($root, 'kongono.data-mapping.json', $output);
$checked = $workflow->check($root, 'kongono.data-mapping.json', $output);
```

Build may leave complete immutable content-addressed outputs when a later stage
fails. It never leaves a partial authoritative file, deletes old outputs, or
overwrites different bytes. Check is non-mutating and requires all exact current
outputs. Each process admits generated data access once; a class collision is a
failure even if the candidate bytes are identical.

The returned value exposes the mapping artifact path/bytes/hash, generated
data-access path/hash and loaded metadata, plus the accepted current Composition
build. It contains no registry, newest-file selection policy, runtime values, or
credentials.

## Runtime use

After checking, load the exact generated wiring and start
`GeneratedDataApplication` with ordered typed startup inputs. For the minimal
data skeleton the sole input is a host-constructed `DatabaseConnector`.

Each operation must be closed explicitly, including when work fails:

```php
$operation = $application->beginOperation();
try {
    $root = $operation->root();
    // Application code asserts its own concrete DataOperationRoot type.
} catch (Throwable $failure) {
    $operation->close($failure);
    throw $failure;
}
$operation->close();
$application->shutdown();
```

Passing the work failure to `close()` preserves it as primary while generated
cleanup attempts proceed in reverse construction order. A cleanup failure
retires its boundary. Do not retry cleanup, retain the operation root, share a
session between operations, or infer transaction policy from this workflow.

## Security review

Failures and logs must not include credentials, DSNs, hosts, database/user
values, SQL, parameters, records, source/artifact/generated bytes, absolute
paths, provider messages, classloader state, stack arguments, or topology. The
workflow performs no network access and reads only explicit bounded contained
files.
