# Database Mapping Engineering Guide

## Define explicit records and source

Create application-owned final readonly record classes with exact native scalar
constructor parameters and public zero-argument accessors. Keep constructor
order identical to mapping field order. Choose an assigned non-null integer or
text identity and at least one non-identity field.

Place one inert `kongono.data-mapping.json` beneath the application root and
pass its relative path explicitly. Do not scan for it or use attributes,
filenames, database schemas, runtime Reflection, or conventions as authority.
Treat it as untrusted data: unknown members, duplicate keys, links, traversal,
invalid UTF-8, unstable reads, and unsupported types must remain failures.

## Build, validate, and publish

Use `MappingArtifactBuilder::build()` during an explicit build/check step. Keep
the returned canonical bytes as derived evidence. Before generation or use,
`MappingArtifactValidator::validateCurrent()` must succeed against the same
application root and source path.

Generate with `GeneratedDataAccessGenerator::generate()`, then use
`GeneratedDataAccessValidator::validateCurrent()` to prove the exact current
artifact and generated bytes. Publish only validated output with
`GeneratedDataAccessPublisher::publish()` into an existing application-owned
directory. The content-addressed result is safe to request repeatedly for
identical bytes; a conflicting existing file is a failure.

Do not edit emitted PHP, substitute a different artifact, bypass current
validation, or check generated output into this repository. The package does
not load generated classes. An application runtime boundary must explicitly
load the exact validated path after confirming no target class is already
defined.

## Construct and use repositories

Construct each generated repository with a caller-owned `DatabaseExecutor` and
`SqlDialectCompiler`. Its public surface is exactly:

```text
find(identity): ?Record
insert(Record): CommandResult
update(Record): CommandResult
delete(identity): CommandResult
```

Assigned identities are always included in inserts. Updates change every
non-identity field under the identity predicate. Deletes use only the identity
predicate. Finds select every mapped column under fixed aliases and limit the
result to two rows. A missing row returns null; two rows are a mapping integrity
failure.

The repository never owns the supplied executor or compiler. Keep session and
transaction close, commit, and rollback in caller code. If an operation must be
atomic with other work, construct the repository with the caller's open
transaction executor. Do not add automatic transaction, retry, savepoint,
provider selection, or lifecycle behavior around it.

## Failure and disclosure handling

Handle the mapping exception marker when the application needs package-level
classification. Preserve primary-plus-cleanup failures: a stream close failure
must not erase a hydration, cardinality, fetch, or provider failure. Do not place
source fragments, mapped values, SQL, parameters, credentials, provider errors,
paths, classloader state, or topology into diagnostic presentation.

Generated repositories may be reused only as far as their caller-owned
executor permits. They have no identity map or mutable unit of work. Concurrent
calls and persistent-runtime retention therefore require the same lifecycle and
concurrency review as direct use of that executor.

## Validation

After changing mapping production code, run focused lint, cache-disabled style,
maximum PHPStan, PHPUnit, architecture, and Hantei checks. Validate freshly
emitted PHP outside the repository with lint, maximum PHPStan, and cache-disabled
style; repair the emitter, never temporary generated bytes. Run the root-owned
PostgreSQL 17.2 acceptance command with caller-supplied binaries to prove real
generated repository behavior and complete cleanup.

## Extension, performance, and non-goals

Version 1 is closed. Application code may own records, sources, build orchestration,
output location, loading, compiler, executor, and higher-level domain services.
It may not silently widen the package vocabulary or claim an extension contract
for relations, custom methods, raw fragments, generated identity, callbacks, or
provider behavior.

Expect bounded build-time filesystem, hashing, parsing, Reflection, generation,
and validation cost. Runtime performs explicit checks and ordinary plan and
record allocation. This is an Experimental Data Mapper facility, not an ORM,
Active Record system, session lifecycle, composition owner, universal
portability layer, zero-overhead abstraction, or Stable API. Phase 6G's outer
package performs exact-current loading and composition integration.
